## 1. What the reference is, and what it is not

`referenceSearch` is `pvs` with four things removed and everything else left in
place, so a disagreement names one of the four.

- Removed: alpha-beta. Every child is searched on `(-INF, +INF)`, so no value is
  a bound, no candidate is skipped, and `Evaluator.evaluate`'s two lazy exits
  (`v1 - b >= beta`, `v1 + b <= alpha`) are unreachable — every reference leaf is
  a full stage-0 + stage-1 + stage-2 evaluation.
- Removed: the transposition table, the proof cache, the killers, the history
  and the ordering pass. `scoreTurns` is never called; candidates are searched in
  the generator's own order.
- Removed: truncation. The meter is armed at 1e15 units, so `meter.exhausted()`
  is never true; the module never enters `engine.searchTurn`, so the watchdog is
  unarmed, `ctx.stop()` is constantly false and `StopAwareSink` never cuts a
  candidate list. The R5 quiescence cap compares against `meter.limit` and
  therefore cannot bind either. A node budget bounds the wall clock instead.
- Removed: LMR, futility, aspiration, extensions and df-pn — which at
  `hard@desktop` are already off in production, so this is a statement about
  future arms and not about the champion.
- Kept: the generator. `generateAt` is the production function; ply 0 uses
  `ctx.gen` (K = 24) and interior plies `ctx.genInterior` (K = 16), as `pvs`
  does. "Full width" is the full width of the SHIPPED candidate list, not an
  exhaustive turn enumeration. Replacing DESIGN §5.4's beam would be a different
  experiment, and it is the audit's "generator difference" classification.
- Kept: the evaluator, through the engine's own `ctx.eval` with the engine's
  weights and `evalFix`; `assertWeights` refuses a `version 0` placeholder.
- Kept: the terminal rules. `terminalScore(p, p.side, ply)` at node entry, and
  `terminalScore(p, mover, ply + 1)` after `makeTurn` for a turn that ended the
  game without flipping the side — `pvs`'s own two calls, same perspectives.
- Kept: `PROVER_FULL` at every node. The reference has no scout nodes, so it
  never lowers to `PROVER_BOUND`; the admissible bound can only UNDER-claim a
  corner mate, so the reference is the stronger adjudication.

Two reference values are computed per position, because the leaf rule is the one
real choice. `refStatic` evaluates leaves with `evaluateLeaf(-INF, +INF)`, which
is pruning-free and window-free. `refQuiesce` evaluates them with
`quiesce(-INF, +INF)`, which is production's leaf rule on the widest window.
The production score must lie in `[min, max]` of the two; equality with
`refQuiesce` is agreement, and inside the interval but unequal is a stand-pat
artifact.

Principal-turn agreement is on the end-state key (`endHi:endLo`), the same
identity `hard:cross-commit` compares, and the bar is "production's principal
turn is in the reference's OPTIMAL SET" — every root candidate whose value ties
the reference's root value. A pruning-free search has an order-independent value
and an order-dependent argmax; reporting a single reference argmax would
manufacture disagreements out of ties, which is E4 lane 3's subject.

## 6. Findings

### F1 BUG — the R5 quiescence cap makes a node's value a function of the rung

`quiesce.ts quiesceCapped` returns true once `s.quiesceWork * 100 >=
meter.limit * 34`, and a capped call returns `standPat` instead of searching.
The threshold is therefore PROPORTIONAL TO THE WORK RUNG, so the value a node
returns at a given depth is not a function of the position and the depth.

Measured on `draw-fuzz-5150-1394-24` (white, turn 5, phase `place`, clock 8), the
DEPTH-1 score with the table on: +3,411 at rung 12,000 and +1,694 at rung 50,000.
The threshold is 4,080 units at rung 12,000 and 17,000 at rung 50,000; the
depth-1 iteration passes the first and not the second, so the same node returns a
stand-pat at one rung and a searched value at the other. (+1,694 is also what
rung 12,000 returns with `setQuiesceCap(false)`, which is the attribution.)
At depth 2 on the same position: +67 at 25,000 and +744 at 50,000.

This is not truncation in DESIGN §5.11.6's sense — it is deterministic and
repeatable — but it has truncation's effect on the table: `pvs` stores `best`
whenever `!s.truncated`, and NOTHING SETS `s.truncated` WHEN THE CAP TRIPS. A
stand-pat value the cap produced is published as EXACT at the node's depth and is
returned to any later node that transposes into it.

Cap sensitivity over the corpus: 6 of 36 positions at depth 2 change their score,
their depth or their principal turn when `setQuiesceCap(false)` is set at the
same fixed work. Two of the six change the principal turn, and on both of those
the completed depth drops by one as well, because uncapped quiescence spends the
rung the second iteration needed: `draw-fuzz-5150-1563-72` (white, turn 13, rung
25,000) `fe19cf10999f0ba0` at depth 2 becomes `1755d63e176d1172` at depth 1, and
`draw-fuzz-5150-1043-66` (white, turn 11, rung 3,000) `54528b9e82ee7953` at depth
2 becomes `fedce91681e45650` at depth 1. Three more change the score at an
unchanged depth (`e1dev-e1-g4-s750`, `e1dev-e1-g4-s730`,
`upkeep-loss-g2-s5_0_2-A-white-t4`) and one changes the score at an unchanged
depth and turn (`draw-fuzz-5150-1394-24`).

FLAGGED CHANGE for a later lane, not implemented here (no `src/ai/hard` file
changes in this lane): mark a capped quiescence return so its parent does not
publish an EXACT value for that node. The obvious implementation — setting
`s.truncated` — is WRONG: `s.truncated` latches for the whole search, so the cap
tripping once would suppress every subsequent store and cost the table its
value. A node-local flag (`quiesce` returns "capped", `pvs` stores only a bound
in the direction the stand-pat is safe in, or stores nothing) is the shape to
price. It sits behind a `HardConfig.searchFix` key like every other E4 candidate,
and it changes fixed-work output when ON, so it owns a determinism re-pin.

### F3 ARTIFACT — production's quiescence is not window-independent

On 19 of the 22 searched rows at depth 2 the production score equals `refStatic`,
and on 16 it equals `refQuiesce`; the 5 rows where it equals `refStatic` and not
`refQuiesce` are the stand-pat rows D1, D2, D4, D5, D6. At those leaves
production's quiescence contributed nothing that the full-window quiescence
found.

The mechanisms are `quiesce`'s three window-dependent exits — `standPat >= beta`
returns `beta`, `standPat + maxPlausibleGain + deltaMarginCc < alpha` skips a
candidate, and `hasTacticalPotential` short-circuits to `alpha` — plus
`Evaluator.evaluate`'s lazy `v1 ± b`. Each returns a bound in the direction of
its own cutoff, which is sound for alpha-beta, and which is exactly why the
production score stays INSIDE the reference interval on 21 of 22 rows. It is not
a bug. It does mean a "depth 2 score" is a bound and not a value, and any E4
claim that reads a score difference as an evaluation difference has to say which
of the two it is reading.

Depth resolves it where the work allows: `ss-spawn-strike-purchase-3` disagrees
at depth 2 and 12,000 units and agrees exactly at depth 3 and 50,000 units.

### F4 IDENTITY GAP — `progressThisTurn` is in neither Zobrist key

Section 5.1. `Kpos` carries the clock but not the flag that decides whether the
clock advances. Two start-of-turn positions cannot differ in it (it is reset at
the boundary), so the gap is unreachable from inside one search and the census
found 0 collisions; but `Kpos` is also the BOOK's key and the SUITES' key
(`core/zobrist.ts`'s own header says so), and a mid-turn position is exactly what
a book or a suite fixture can carry. FLAGGED as a documentation defect at least:
`zobrist.ts`'s key list should say that `progress` is deliberately excluded and
why, or `progress` should join `Kturn`.

### F5 IDENTITY GAP — 15 unverified bits in the macro key

Section 5.3. Not observed in 1,174 stores. It is a sizing fact, not a bug: at
`ttBitsMacro` 19 the false-hit rate among random distinct keys is 2^-49, and the
E4 plan's rungs do not store enough entries for it to matter. It belongs in the
record because a later lane that raises `ttBitsMacro`, or lowers it for the phone
profile (15 bits, 2^13 buckets, 19 unverified bits of `lo`), moves it.
