## 1. The flag block, and why the champion's hash does not move

- `src/ai/hard/config.ts` gains `interface EvalFix` and `HardConfig.evalFix?: EvalFix`.
  - `infiltrationPerAnchor` (B3), `inv3RetreatConjunct` (B4), `rentOnce` (B5),
    `relocationCompare` (B1), `rot180TieOrder` (B2); all optional, all read as
    `=== true`.
- ABSENT IS NOT `false`, and that is the whole hash argument.
  - `lab/hard-ai/ladder/identity.ts canonicalJson` drops a key whose value is
    `undefined` (`if (source[key] === undefined) continue`), and
    `hardResolvedConfig` builds the configuration as `{ ...DESKTOP, ...patch }`.
  - `makeConfig` never writes `evalFix`, so the key is not on DESKTOP, LAB,
    MIDRANGE or PHONE at all — a spread cannot add a key that does not exist —
    and the serialised champion is byte-for-byte the string it was.
  - Writing `evalFix: {}` or `evalFix: { rentOnce: false }` into a profile WOULD
    put the key into the serialisation and move the hash for no behaviour
    change, orphaning every E1/E2/E3 row measured under `4e7afdf76b32fad…`.
    This is the contract `time.calibrateCold`, `time.ladderStep` and
    `iterationGate` already carry, and the three comments there say so.
  - Verified: `resolvedConfigHash('hard@desktop', {mode:'wall', ms:3000})` prints
    `4e7afdf76b32fadfab2d11577cb610c8f9f1a491b5153e70b87b0774403600cd` at this
    head; each arm prints a hash of its own (§3).
- How a flag reaches the four readers: `NodeTables.evalFix`.
  - `HardEngine`'s constructor stamps `config.evalFix ?? null` on each of the
    per-ply `allocTables()` nodes and passes the same block to its `Evaluator`,
    which stamps its own node.
  - `tables/economy.ts` (B1, B2, B5), `eval/invariants.ts` (B4) and
    `eval/features.ts` (B3) all take a `NodeTables` already, so NOT ONE
    normative signature in DESIGN §4.8/§4.12/§4.15 changes and not one of the
    ~40 existing `allocTables`/`buildTables`/`extract`/`invariantBits`/
    `economyDP` call sites in `src`, `lab` and `tests` is touched.
  - `allocTables()` returns `evalFix: null`, so every lab instrument, oracle and
    test that builds its own tables is the champion unless it says otherwise.
  - The one additive signature is `economyStayInPlace(p, side, out, fix?)`:
    DESIGN §4.12 gives that function no tables, and the oracle must compare the
    DP against a baseline computed under the same flags.
  - Consequence worth naming: a module-level "active flags" global would have
    been simpler and WRONG — a ladder row runs both arms in one process, so the
    block has to be per engine.

### B4 — `Inv3RetreatSquare` drops DESIGN §5.13 row 3's `retreats > 0`

- The defect, judge 3: DESIGN.md:1448 reads "some own unit with `material ≥ 400`
  has `approach == RETREAT` **and the attacker has `retreats > 0`**";
  `eval/invariants.ts` tested only the first half, and `t.retreats[slot]` —
  computed by `tables/approach.ts`, written by `buildTables` — was read nowhere
  in the evaluator.
- The flag: `inv3RetreatConjunct` adds `&& t.retreats[slot] > 0`.
- Reproduction on the three fuzz positions E3.1 named (`fuzz-1000.jsonl`, static
  evaluation, both sides):
  - `fuzz-5150-1651-27`: bit set for BOTH sides with the flag off, cleared for
    both with it on; the me−them feature is 0 either way, so the difference hid
    a −250 cc charge on each side's absolute score.
  - `fuzz-5150-531-27`: White 0 / Black 1 off, 0 / 0 on; the feature moves −1 → 0
    and White's static score 2,403 → 2,153 cc (the penalty was Black's, and it
    was not DESIGN's penalty).
  - `fuzz-5150-1044-37`: White 1 / Black 1 off, White 1 / Black 0 on — White's
    attacker HAS a retreat square and Black's has none, so a cancelled pair
    becomes a real +1 (score −2,886 → −3,136 cc from White's view).
- Reproduction on a new authored fixture PAIR (`tests/ai/hard/eval-correct.test.ts`,
  built by `buildState`, nothing on disk edited): white `metal_1` at (4,4) under
  a black `fire_2` at (6,4), with a spare white body at (0,9) so the kill would
  not end the game (`approach.ts`: a lethal hit on the defender's last unit is
  STRAND, not RETREAT).
  - Member A leaves the attacker's escape squares open: `t.retreats = 1`, the bit
    stays set with the flag on, and the me−them feature is +1 for White at
    w = −250.
  - Member B adds three white bodies at (6,2), (6,6) and (8,4) so every escape
    square is inside White's strike: `t.retreats = 0`, and the bit clears.
  - The invariants suite's own `inv3` pair cannot do this job: L7-F5 shows the
    opponent carries the pair's bit, so the feature reads 0 on the member built
    to be punished.
- Frequency, judge 4, `fuzz-1000`, 2,000 side-positions: the bit fires 965 times
  with the flag off and 22 times with it on — 943 of 965 firings, 97.7%, are the
  case DESIGN excludes. (`repro.json` `b4.fuzz1000`.)
- What the flag does NOT fix, and it is a new finding: with B4 on, five of 1,000
  fuzz positions disagree with their own rot180 + seat-swap mirror on
  `Inv3RetreatSquare`, 250 cc each.
  - Traced on `fuzz-5150-4-132`: one lethal attacker in each spelling, at
    mirrored squares 43 and 56, same class and same cost `d = 2`, and
    `classifyApproach` returns `retreats` 0 in the position and 1 in the mirror.
  - Cause: `retreats` is `|reach(attackSquare, speed, 1) \ strike[defender]|`
    and `attackSquare` is the cheapest square adjacent to the target; a tie
    between two adjacent squares is broken by scan order, which rot180 reverses.
  - The champion never saw it because it read `retreats` nowhere.
    `tables/approach.ts` is not lane 12's file; proposed as a sixth flag in
    `amendments/lane12.md` §A2.

### B5 — rent is charged twice

- The defect, judge 4 and judge 3: `tables/economy.ts` subtracts `upkeepDue(p, side)`
  on all six horizon turns of `stream`, and `Rent` charges the same sum once at
  `RENT_PV = 422`, the six-turn present value; DESIGN.md:1348 says rent is
  "charged **once**, as `Rent`".
- The flag: `rentOnce` makes `stream` carry income only.
- Reproduction on lane 3's ledger position `loss-g2-s5_0_2-A-white-t4`
  (exam `dev.jsonl`, `loadCaseState`, White to move, turn 4), promoting White's
  `water_1` at (1,1) to `water_2` — +1 crystal per turn of upkeep at an
  unchanged mining rate of 2:
  - Flag off: `Rent` −422 cc and `EconDelta` −320 cc, **−742 cc** for one crystal
    per turn — 1.76 × `RENT_PV` measured, 1.72 × derived. White's `stream` falls
    1,655 → 1,275.
  - Flag on: `Rent` −422 cc and `EconDelta` 0, **−422 cc**. `stream` 1,655 →
    1,655.
  - The rest of the perturbation is unchanged in both readings (`Material` +400,
    `ElementCoverage` +150, `TierClimb` 0), which is what makes the isolation
    exact.
- `turnsToInsolvency`, `Insolvency` and `RunwayCliff` — the synthesis asks for
  these three to be reported together — DO NOT MOVE, by design and by
  measurement.
  - By design: the running balance is a cash-flow projection, not a score, and
    the bill is one the rules really do collect every turn
    (`src/game/upkeep.ts`). Dropping upkeep there would make the engine blind to
    upkeep elimination — a different bug from the one B5 fixes, and the two
    upkeep-elimination loss roots (L6-F4) are exactly where that would hurt.
  - By measurement: over `fuzz-1000`, 2,000 side-positions, the flag changes
    `turnsToInsolvency` on 0, `Insolvency` on 0 and `RunwayCliff` on 0
    (`repro.json` `b5Balance`). `out.upkeep[]` still reports the real bill.
- Direction warning kept from the synthesis: judge 1 at the two
  upkeep-elimination loss roots says the fix REDUCES the adviser's margin. B5 is
  correct, not necessarily strong; if `eval-correct-v1` loses its row, B5 is the
  first flag to isolate.

### B3 — `Infiltration` is identically zero

- The defect, judge 4, proved on all 10,000 square pairs (lane 1) and reproduced
  here: `tables/geometry.ts` counts ordered pairs (own unit at `s`, enemy unit at
  `a`) with `s ∈ RECT[enemy][a]`; with the corners at squares 0 and 99 that
  relation is symmetric, so both sides' counts are equal and the FEATURE — the
  difference — is 0 on every legal position. Measured 0 on 1,000 of 1,000 fuzz
  positions with the flag off, at a DESIGN §5.12.1 weight of +90.
- The flag: `infiltrationPerAnchor` counts what DESIGN §5.8 and
  `core/spawn.ts:173-185 anchorsVoidedBy` define — the number of DISTINCT enemy
  anchors whose rectangle holds at least one of my bodies.
  - `anchorsVoidedBy` is not called: it answers "if an intruder stood on the
    EMPTY square `s`", and passing it one of my own placed units makes that
    square part of the occupancy it skips — the bug DEVIATIONS M9 records and
    "fixed" into the current pair count. The flag borrows the semantics
    (an anchor already voided is not voided twice), not the call.
- Reproduction on the 10-vs-2 position `fuzz-5150-4-377` (12 white units, 10
  black, Black to move, turn 60):
  - White voids all 10 of Black's anchors; Black voids 2 of White's 12.
  - Feature 0 → **+8** from White's view, −8 from Black's, i.e. 720 cc at w = 90.
  - The rotated copy (`mirror180`, seats swapped) gives +8 for the same player —
    the test on the DIFFERENCE that `tests/ai/hard/geometry.test.ts:176-213`,
    which guards the per-side count only, cannot give. Both directions are
    asserted in `eval-correct.test.ts`.
- Frequency, `fuzz-1000`: non-zero on **294 of 1,000** positions, median 180 cc
  when non-zero, max 720 cc — lane 1's prediction (294/1000, typically 180 cc)
  reproduced exactly.
- Cost of the flag: it never fires on the 16 exam loss roots, so B3 is not a
  loss-corpus concept; it is a feature the champion pays for and never collects.

### B2 — the relocation tie order is not rot180-invariant

- The defect, judge 4: `bestRelocationTarget` breaks an exact argmax tie by the
  lowest square INDEX (ascending scan, strict `>`), and the board's own symmetry
  maps `s ↦ 99 − s`, which reverses that order.
- The flag: `rot180TieOrder` breaks the tie in the MOVER'S OWN corner-relative
  frame — key `s` for White (corner square 0), `99 − s` for Black (corner square
  99) — which the mirror transform carries with it, so the two spellings of one
  position pick mirrored squares.
- Reproduction with the flag off, from `eval-audit/fuzz-1000/violations.json`:
  - `fuzz-5150-1097-11`: `RelocationDebt` −1 on the position, 0 on its mirror
    (static score 248 vs 188 cc).
  - `fuzz-5150-1651-27`: `EconDelta` −3 vs −4, `RelocationDebt` −10 vs −9
    (375 vs 235 cc).
  - `fuzz-5150-1044-37`: `EconDelta` 5 vs 6, `DepletionWaste` 7 vs 6
    (−2,886 vs −2,776 cc).
- With the flag on all three mirror pairs agree on all 58 features, scores
  included.
- Corpus scan, `fuzz-1000`, each position against its own rot180 + seat-swap
  mirror (`repro.json` `b2.scans`):
  - flag off: **585 of 1,000** violate, mean |Δ score| 211.4 cc, max 1,440 cc,
    in exactly three features — `RelocationDebt` 501, `EconDelta` 342,
    `DepletionWaste` 318 — reproducing lane 4's numbers to the position.
  - `rot180TieOrder` on: **0 of 1,000**, in any feature.
  - B1 alone: 671 (it relocates more often, so it ties more often); B3 alone:
    585; B4 alone: 587 (the five new `Inv3` cases above); B5 alone: 589.
  - All five together: 5, all `Inv3RetreatSquare`, 250 cc each — B4's residue,

### B1 — the relocation trigger is not monotone in reserve

- The defect, judge 4: a board that strictly GAINS a crystal projects less
  income, which no rule of the game can do. `economy.ts` relocated a miner only
  when its cell was completely dry (`take === 0`), so one residual crystal
  delayed the whole schedule.
- The flag: `relocationCompare` makes the trigger a COMPARISON — relocate when
  the best reachable cell, discounted for the walk exactly as
  `bestRelocationTarget` already discounts it, beats what is left of this cell
  (`PST_MINE[def][reserve]`, the same quantity on the same scale).
  - On an already dry cell the floor is `PST_MINE[def][0] = 0` and the flagged
    rule IS DESIGN's rule.
  - On the turn the cell empties it fires one turn sooner than DESIGN's — the
    turn of mining nothing the champion spends confirming what the reserve count
    already said.
- Reproduction of lane 3's perturbation at `loss-g2-s5_0_2-A-white-t4`, +1
  resource layer at (1,1) under White's `water_1`:
  - Flag off: score **−130 cc** (`PstMine` +60, `EconDelta` −160,
    `DepletionWaste` −30); White's projected income `[7,4,2,7,3,2]` (25 crystals)
    → `[7,5,0,7,5,0]` (24), `stream` 1,655 → 1,608.
  - Flag on: score **+60 cc** (`PstMine` +60 alone); income `[7,7,7,6,7,5]` (39)
    at both reserves, `stream` 2,500 at both. The non-monotonicity is gone at the
    canonical case, and the flagged DP projects 14 more crystals over the horizon
    at a `relocationDebt` of 1,260 cc against the champion's 420.
- The oracle check the synthesis asked for is committed:
  `lab/hard-ai/oracles/economy.ts` gains a fifth check — for every sampled
  position, side and living miner whose cell is not full, add one crystal under
  that miner and require `economyDP().stream` not to fall. Only `p.reserve`
  moves, so the comparison isolates the DP.
  - At `--positions 2000` (13,183 miner perturbations, both sides), flags off:
    **4,102 violations (31.1%)**. B1 is not an n = 1 curiosity.
  - `--eval-fix b1`: **10 (0.076%)**. The bundle of all five: **6**.
  - `--eval-fix b2`: 4,034; `--eval-fix b5`: 4,104 — neither is about this bug.
  - The four M8 criterion fields (`streamMismatch`, `relocationMonotone`,
    `insolvencyMismatch`, `pstMaxErr`) are 0 / true / 0 / 0 in EVERY
    configuration, so the M8 gate is green with the flags on and off. The new
    check is not part of that criterion and sets the exit code only under
    `--require-reserve-monotone`; making a known open defect fail M8 would have
    turned a documented bug into a red gate for every milestone downstream, which
    is the coordinator's call and not this lane's.
  - Under `rentOnce` the literal stream reference drops its upkeep leg too;
    without that the oracle would report 144 "mismatches" that are only the rent
    the flag deliberately removed.
- The 10 residual violations, named: all in one `openings.jsonl` family
  (`opening-279`, `-281`, `-283`, `-293`, `-302`, `-327`, …), all Black, all the
  same square 98, all `stream` 2,178 → 2,130 (−48 cc, −2.2%).
  - Mechanism: one more crystal moves `PST_MINE` across a quantisation step, the
    comparison then keeps the miner one turn longer, and the relocation's payoff
    falls off the six-turn horizon. It is a horizon-truncation artifact of a
    greedy per-miner rule, not the dry-cell cliff B1 names.
  - So B1's status is: fix direction established and 99.76% of the violations
    removed, monotonicity NOT proven. The flag ships as an arm with this residue
    documented; a monotone rule needs a stay-versus-move schedule per miner,
    which is a DESIGN §5.8 change and not a flag.
