# Muju mobile play interface — 2026-09-07

This UI lane is based on AI-correctness commit `fc854fb`. It changes presentation and input handling; unit stats, costs, build times, turn rules, and AI implementations stay in the separate balance lane. The authoritative reducer remains unchanged.

## Player experience

- The play screen uses the available dynamic viewport height and iPhone safe-area insets. The complete board, resource summaries, phase indicator, selected-unit information or shop, undo, and phase controls fit together. Landscape places the controls beside the board.
- Quiet dots indicate reachable cells: solid for one action, hollow for farther destinations. Resource numbers are optional through **Depths**. Amber shading still represents resource depletion.
- Tap a destination to preview its route, action cost, remaining actions, and mining yield; **Confirm move** commits it. Attacks preview actual modified attack power versus current defense and the resulting elimination or remaining defense. Cancel and changing destinations do not spend actions.
- Unit details occupy a reserved panel instead of covering the board or resources. Mining displays the actual yield; upgrades display catalogue-derived next-tier stats, cost, and the existing promotion eligibility restrictions.
- The shop presents six elements and four tiers with one unit's details, build time, cost, and a specific unavailable reason. Reinforcements appear in a compact horizontally scrollable queue when needed.
- The elemental counter cycle remains visible in the footer. Units, help, and extended match statistics use focus-trapped dialogs. The help starts with the actual phone interaction model. New Game is protected against accidental resets.
- Enemy reach is opt-in and explicitly represents current speed with six actions. The old automatic hypothetical-upgrade range is removed.
- The resource ledger stays on the human side during an AI turn. Opponent resources and build queue are hidden. Public field spending is labeled separately from total spending.
- Native buttons make whole occupied squares tappable. Tab navigates controls; N cycles units; M mines; U upgrades; Cmd/Ctrl+Z undoes. Enter confirms a focused board preview and Escape cancels it. Game shortcuts do not interfere with dialogs or native button activation.

## Verification

- `npm run build`: TypeScript and Vite pass.
- `npm test`: all 508 existing game/AI tests pass.
- `npm run test:e2e`: 15 browser tests pass against the built preview. Coverage includes no document/panel overflow in placement, move previews, and building at 320×568, 375×568, 375×667, 390×664, 393×706, 390×844, 430×932, 844×390, and 1280×900; real move/attack confirmation; mining; undo; building; promotion restrictions; native dialog focus; keyboard interactions; and AI-resource privacy.
- WebKit 26.0, using installed Playwright 1.58.2, additionally passed touch selection, preview, confirmation, and no document overflow at 390×664, 375×568, and 844×390. These are browser-engine checks, not a physical iPhone/Safari-toolbar test.
- At 390×664, the original screen measured 1,166px in document height. The updated screen measures 664px with the board and controls visible. The action-phase board is approximately 336px square. On very short screens the board scales down further; confirm-before-commit helps with smaller cells.

To repeat the browser suite, build and serve Muju on a free local port (bind `127.0.0.1`), then run `MUJU_BASE_URL=http://127.0.0.1:PORT/muju/ npm run test:e2e`. The config defaults to local Chrome; `PLAYWRIGHT_CHANNEL` overrides it, and CI uses bundled Chromium. The default preview URL is port 8927. Tests intentionally do not start or restart a shared server.
