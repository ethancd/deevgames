# E2.3 — Two interior-only arms, registered and mechanism-checked

Lane 4, branch `claude/hard-ai-e2-lane4`, 2026-09-16.
Follow-up to `E2.2-COVERAGE-TRACE.md` §8, which named two candidate changes.
This file registers them, then tries to falsify each one's MECHANISM with the
E2.2 trace before any contest time is spent. One of the two is falsified here.

## 1. The arms

Both move the INTERIOR half of a shape knob and leave the root half at
DESKTOP's value. E2.2 found 28 of 28 traced root targets already in the root
list, so a root-side widening cannot recover an analysed loss and would only
cost time at every root node.

## 2. Mechanism check with the E2.2 trace

`lab/hard-ai/coverage/run.ts --arm <name>` measures with the arm's cones while
the CAPTURE pass stays on the fixed reference shape, so an arm run and a base
run measure the SAME targets and their per-row stages compare directly. Every
run reports identical root node totals (8,402), which is the arms' root-untouched
claim measured rather than asserted.

Commands (each a few seconds to ~75 s, generator-only, no search):

```
cd muju
for arm in interior-action-wide interior-place-wide; do
  node --import tsx lab/hard-ai/coverage/run.ts \
    --analysis lab/results/hard-ai-e1/e1.1-diag/analysis --arm "$arm" \
    --out lab/results/hard-ai-e2/coverage/arms/$arm/e1.1-losses --label "$arm-losses"
  node --import tsx lab/hard-ai/coverage/run.ts \
    --recall-replies 55 --arm "$arm" \
    --out lab/results/hard-ai-e2/coverage/arms/$arm/recall-replies --label "$arm-recall"
done
```

### 2.3 What the two tables say

**`interior-action-wide` is falsified as stated, before any contest.** It does
recover beam misses — 3 of the 21 recall items, all of them previously `beam` —
which confirms E2.2's attribution. But on the 14 losses it recovers NOTHING and
costs six targets that base had: five fall to `keep` and one to `final-k`. The
mechanism is visible in the trace. A wider beam reaches more turn boundaries per
place plan while the per-plan `keep` list stays at 4 and the interior `K` stays
at 16, so the extra boundaries DISPLACE the target instead of adding to it.
Present reply targets on the loss corpus go 19 → 13. That is a net loss of
coverage at 2.30× the reply generation cost, and it is the most likely reading of
E1.3's `action-width-wide` ladder row (+95 then −5 at equal time): the arm buys
recall on easy nodes and loses it on the nodes the losses came from.

**`interior-place-wide` survives on the loss corpus and does nothing on the
recall corpus.** On the 14 losses it clears all four `combo` misses and, as a
side effect of the extra plans, three `beam` misses as well: 7 of 9 recovered,
zero new misses, present 19 → 26. On the recall corpus it recovers none of the
21. Stated plainly, as asked: the single recall `combo` row does have its buy
set inside `planCount = 12` and outside `comboCount = 8`, and the arm DOES clear
that rung — the row moves from `combo` to `beam` — but the interior beam still
cannot walk to that end position, so it does not become present. The arm's
mechanism is confirmed; its yield is entirely on the loss corpus.

The two corpora disagree because they ask different questions. The recall reply
items are corpus-tail positions after the engine's own best turn — mostly quiet
nodes where the place phase often auto-advances (13 of the 20 base `beam` misses
have `comboCount = 0`, so no placement widening can reach them). The loss reply
nodes are positions the champion actually lost from, where the place phase is
live and a buy set is what the refutation needs.

## 3. Cost model

`GenStats.nodes` summed over every MEASURE generation, split by cone. Root
totals are byte-identical across all three configurations, which is the point of
an interior-only arm.

| arm | reply nodes/generation (losses) | ratio | reply nodes/generation (recall) | ratio | root nodes/generation |
| --- | --- | --- | --- | --- | --- |
| base | 196 | 1.00 | 64 | 1.00 | 300 |
| `interior-action-wide` | 451 | 2.30 | 137 | 2.14 | 300 |
| `interior-place-wide` | 265 | 1.35 | 72 | 1.13 | 300 |

Forecast for an equal-time row. Generation is one of several costs in a search
(DESIGN §5.11.6 charges `WorkClass.GEN` per place plan, and the reply node is
one ply of many), so the reply-node node ratio is an upper bound on the
whole-search slowdown, not the slowdown itself. `interior-place-wide` at 1.35×
reply generation should cost single-digit percent of search throughput;
`interior-action-wide` at 2.30× is the expensive one and it is also the one with
negative coverage on the loss corpus.

## 4. Recall diagnostic

Run the way E1.3 ran per-arm recall, all three arms at one commit, on the heavy
queue's free slot:

```
cd muju
npm run hard:ablate -- --arms base,interior-action-wide,interior-place-wide \
  --reply-positions 60 --deep 2000 --out-dir lab/results/hard-ai-e2/ablate
```

Artifacts: `lab/results/hard-ai-e2/ablate/<arm>/recall.json`.

All three arms measured at ONE commit, so `base` is re-measured here rather than
quoted from E1.3: the derived corpus has grown since (134 root items now against
E1.3's 127), which moves base's root columns and would make a cross-run
comparison wrong. E1.3's rows are shown beneath, at their own corpus.

Readings.

- Root `top1` is identical to base for both arms, to four decimals, as it must
  be: neither arm moves a knob a ROOT item reads. That is the arms' root-untouched
  claim measured a second way, independently of the coverage runs' node totals.
- `interior-action-wide` moves `replyTop1` 0.3636 → 0.4545, the largest reply
  recall any arm has produced — above E1.3's `action-width-wide` (0.4364), which
  moved root and interior together and cost root time to do it.
- `ceilingReplyTop1` is unchanged at 0.7818 for both arms, so the reference
  truth did not move and the comparison is clean. (`reply-wide` DID move it,
  0.7818 → 0.8727, which is why its `replyTop1Share` fell while `replyTop1`
  stood still — E1.3's puzzle, now explained by E2.2: the added interior
  candidates were never the ones the beam could reach.)
- `meanCheapCandidates` barely moves for `interior-action-wide` (18.5 → 18.7)
  and not at all for `interior-place-wide`. Neither arm is buying recall by
  simply listing more turns, which is the failure mode EPIC-PLAN E2's exit
  criterion rules out ("a larger K by itself is not success").
- `interior-place-wide` moves every recall column by ZERO. The recall
  instrument cannot see it at all, which is exactly what the coverage trace
  predicted for the recall corpus in §2.2 and §2.3.

The two instruments therefore agree, and they disagree about which arm wins
because they measure different position populations — §2.3.

## 5. Recommendation

**First E2 screening row: `interior-place-wide`.** Second choice: nothing.

The case for it. On the corpus that represents the actual failures — the reply
nodes of the 14 analysed losses — it recovers 7 of 9 missing refutations with
zero new misses, and it clears the rung the trace blamed (4 of 4 `combo` rows).
It costs 1.35× reply generation nodes and nothing at the root, so the equal-time
price is small and predictable. It moves one factor, its hash is registered, and
its mechanism was checked before the row rather than after.

The case against it, stated because a screening row should know what it is
risking. The recall diagnostic gives it nothing — every column equals base — so
this row is being funded on the coverage trace alone, which is a 28-row sample
over 14 games. And recovering a refutation at a reply node is not the same as
choosing a better move at the root: the search still has to score it. If the row
comes back at 0.5 with an interval spanning zero, the honest conclusion is that
reply-node coverage was not the binding constraint, not that the arm needs a
wider setting.

**Do NOT spend a row on `interior-action-wide` yet**, despite it owning the best
`replyTop1` on record. Two reasons.

1. The trace says it loses coverage where the losses are: present reply targets
   on the loss corpus go 19 → 13, with five new `keep` misses and one new
   `final-k` miss. A wider beam reaches more boundaries per place plan while
   per-plan `keep` stays at 4 and interior `K` stays at 16, so the extra
   boundaries displace the target rather than adding to it.
2. E1.3 already priced the near-neighbour `action-width-wide` at equal time:
   +95 then −5, not retained. Re-running the same knob at 2.30× reply generation
   cost, against a trace that predicts the regression, is spending a row to
   re-learn E1.3's answer.

What `interior-action-wide` is good for is the NEXT diagnostic, not a contest.
Its six new misses are a clean, cheap prediction to test: if raising the
interior `keep` floor or interior `K` alongside the wider beam removes them, the
beam's recall is real and the displacement is a sizing bug. That is a
two-factor change and belongs in E2.4 ("adaptive candidate selection"), not in a
one-factor E2.3 row; the coverage trace can settle it in seconds without a
contest, and lane 4 can run that check on request.

One more thing the histogram asks for and neither arm supplies: 13 of the 29
present recall reply rows and 11 of the 28 present root rows are present only
because a FORCED INJECTION produced them. The injection layer is carrying a
large share of reply-node coverage. Whether widening it beats widening the beam
is a question no registered arm currently asks.
