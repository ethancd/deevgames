# Hard AI under Phasing: preregistered release rule

**Status: adopted 2026-09-18 with default parameters. Nothing here has been run.** The
file is frozen when the first Gate 1 row starts; after that, amendments are appended
with a date and reason, never edited in.
It plays the role `RELEASE-2026-09-18.md` played for Standard, written *before* the
evidence instead of after it.

## Why this exists

Phasing becomes the main and only Muju rule set (see
`../changes/2026-09-phasing-only.md`). Every existing Hard AI strength number —
including R2, 51/0/13, +237 Elo [+141, +385] vs `aiv2-hard` — was measured under
Standard and says nothing about Phasing. The Hard engine keeps a complete replica of
the rules, its evaluation encodes Standard timing, its tuning corpus is Standard
self-play, and its sealed openings were generated by Standard scripted bots and have
been consumed. Today the honest statement is: **Hard AI strength under Phasing is
unmeasured**, and the engine cannot legally play it.

## Fixed definitions

- **Rules revision:** `muju-phasing-1` semantics as specified in
  `../PHASING-2026-09-16.md`, to be folded into `SPEC.md` v3.0. Any rules edit after
  sign-off voids rows measured before it.
- **Reproducibility anchor:** the last commit supporting both rule sets is tagged
  `standard-final`. Standard pins and `RELEASE-2026-09-18.md` remain valid evidence
  *for that tag only*.
- **Engines:** `hard@desktop` (Phasing-only replica; `pack` rejects any other state)
  and the independent baseline `aiv2-hard` (legacy `AIEngineV2` + WASM kernel ABI 7,
  ported minimally to Phasing).
- **Identity:** every row records git revision, content hashes of `src/ai/**`,
  `src/game/**`, the WASM binary and `package-lock.json`, the resolved-config hash per
  engine, the rules revision, `WEIGHTS_VERSION` and the book magic. Rows are never
  pooled across differing identities.

## Gate 0 — correctness veto (must hold before and during every row)

Any failure voids the row; none may be waived by a good score.

1. `hard:perft` equals canonical macro-turn perft on all re-frozen fixtures, including
   low-bank Prepare fixtures; perft keys include pending summons.
2. `hard:fuzz`: 0 divergences on the transition, legality, prover **and arrival/refund**
   surfaces; `unmake(make(a))` identity after every action.
3. `verifyTurn`: 0 divergences over a full dev row.
4. Fixed-work **TT-on vs TT-off PV equivalence** (guards the pending-summon Zobrist plane).
5. Prover verdicts agree with `analyzeHomeDefense`, including UNKNOWN at the node cap.
6. In every ladder game: **0 illegal actions, 0 replica divergences, 0 engine
   fallbacks** (`packError`, `engineError`, `divergence`, `invalidSuffix`, `emptyPlan`,
   `workerError`). A fallback means the game was partly V2 vs V2.
7. Suites at or above floors pinned *before* tuning, on frozen fixture versions:
   tactics and invariants re-verified as Act-phase roots; home-mate re-authored for
   act-only rescue; economy re-derived; spawn-strike retired; new summon-disruption and
   home-fortify suites. Adjudicated games ≤ 1%.

## Gate 1 — baseline sanity (blocks Gate 2; passing Gate 2 does not excuse failing it)

A strawman baseline would make the strength row meaningless. Before any Hard-vs-V2 row:

- `aiv2-hard` beats each Phasing-aware scripted L2 bot (Rush, Expand, Balanced) with
  score > 0.5 and an Elo interval excluding 0, and reaches at least **60%** of its
  historical Standard Elo margin over the same bots (a port that loses more than that
  is treated as crippled and must be fixed before it is used as a baseline);
- `aiv2-hard` beats `aiv2-medium` (interval excluding 0);
- purchase rate per game and inactivity-draw rate fall inside a band fixed from the
  scripted-bot round-robin **before** the V2 rows are run;
- 0 illegal actions.

## Gate 2 — strength row (mirrors R2)

- **Arms:** `hard@desktop` vs `aiv2-hard`, paired and seat-mirrored, handicaps h0 and h3
  reported as strata, `wall:8000`, strict legality, single preregistered seed.
- **Openings:** `p1-sealed.jsonl`, generated by **scripted Phasing bots only** (no engine
  under test generates openings), allocation dev/val/sealed sha256-pinned in
  `ALLOCATION.md` and frozen before the first pair. Tuning (`hard:corpus`,
  `hard:texel`) uses dev only; model selection uses val only; **sealed is consumed once**.
- **Size and seed:** 32 pairs, seed **20260953** (the next in the R1/R2 series
  20260951, 20260952). The only permitted change is upward: if `hard:forecast` on
  **dev** data shows 32 pairs is underpowered at the observed Phasing draw rate, the
  larger cap is appended here as a dated amendment *before* the sealed file is opened.
- **Falsifiable rule:** the row passes iff score > 0.5 **and** the Elo interval excludes
  0 **and** SPRT(0, +100; α = β = 0.05) accepts H1 or, at the cap, does not accept H0.
  "Inconclusive" is reported as inconclusive, not as a pass.
- **No reruns:** a failed sealed row is a failed row. A new attempt needs a new sealed
  split and an appended amendment explaining what changed.

## Gate 3 — responsiveness

Desktop p95 ≤ 6,000 ms; phone p95 ≤ 3,000 ms; overruns reported. Standard shipped with
phone/tablet timing, memory and p99 unmeasured; those remain listed as unmeasured unless
measured here. They are not silently inherited as passed.

## Known threats to validity (to be reported with the result)

More inactivity draws under Phasing (no summon-and-strike, delayed arrivals) compress

### A5 — 2026-09-19: the Gate 1 budget is calibrated per SEARCH, with a per-turn ceiling

Written before the adapter is changed and before any eligible calibration or row exists. Justified without reference
to any score.

**Defect in A3 §3 as written.** A3 defined the row's fixed-work budget as "the median search work consumed per own turn"
in wall mode. The shipped loop (`useAI` + the worker's turn mode) does not spend a turn's work in one piece: it runs a
search, replays the returned plan, and runs a FURTHER full search only when the plan runs out or stops being legal
(typically 1-3 searches per own turn; a Phasing turn also has an upkeep decision and a Prepare phase under the same
mover). A single per-turn number cannot reproduce that: the adapter built to A3's wording gave its first search about 75%
of the turn and funded every follow-up search with exactly 1 work unit (44 of 48 follow-up Act searches, 24% of hard own
turns, in the ineligible pilot `gate1-p2-pilot-2026-09-19`), i.e. a weakened baseline — the same kind of defect A3 was
written to remove.

**Replacement.** The calibration measures, per engine, in wall mode at the shipped quick allowance on the dev openings:
(a) the median work of ONE search (`workPerSearch`), by search kind where the shipped loop distinguishes them (Act
search, upkeep decision, Prepare search); (b) the distribution of searches per own turn; (c) the median total work per
own turn. The row's adapter funds EACH search with that kind's calibrated `workPerSearch` and stops a turn only at a
per-turn ceiling set to the calibration's 95th-percentile total work per own turn, so a fixed-work turn is spent the
way a shipped wall-clock turn is. The report header prints, side by side for calibration and row: work per search by
kind, searches per own turn (median and distribution) and total work per own turn; a row whose median searches per own
turn differs from the calibration's by more than 1, or in which more than 2% of searches were funded below half their
calibrated `workPerSearch`, is INVALID. Everything else in A1-A4 stands. Seeds: row 20260960 (unused so far); the next
pilot uses 20260963 (20260961 void per A4, 20260962 consumed by the defective-adapter pilot).

### A7 — 2026-09-22: rules revision `muju-phasing-3` — the kill clock

**Owner decision (Ethan, 2026-09-22).** The twenty-ply inactivity draw clock is replaced by a
ten-ply **kill clock** decided on mined totals: ten kill-free player turns end the game at once,
and the higher **mined total** (every crystal a side's units took from the board across the whole
game, Black's starting handicap folded in, never reduced by spending) wins; equal totals draw.
`#` (home-checkmate) is withheld once the invader's next turn start is no longer guaranteed for
that hand-off (`c >= limit - 1`, i.e. `c >= 9`). What resets the clock is unchanged: only an
attack that removes a unit. Full rule text: `docs/changes/2026-09-22-kill-clock.md` and SPEC v3.3
§9. Recorded, in parallel, as `docs/changes/2026-09-22-p3-retune-SPEC.md`, the campaign this
amendment belongs to.

**Why this needs an amendment.** "Fixed definitions" says any rules edit after sign-off voids
rows measured before it. The rules revision therefore advances from `muju-phasing-2` to
**`muju-phasing-3`**, and every identity hash carried by a ladder row, a suite measurement or a
Gate 1 row changes with it, exactly as A4 advanced `muju-phasing-1` to `muju-phasing-2`. The
inactivity-draw rate that Gate 1's bands were frozen from is not merely re-scaled by this change,
the way the 10-to-20-ply widening re-scaled it: under the kill clock an actual inactivity draw
(`GameRecord.inactivityDraw`, meaning `victoryReason === 'inactivity'`) is structurally
impossible — the tenth kill-free ply is now a decided `winType: 'kill-clock'` position in the vast
majority of games, with a real winner, and only an exact mined-total tie draws. A band computed
from a quantity that can no longer be nonzero is not describing the same behaviour it described
