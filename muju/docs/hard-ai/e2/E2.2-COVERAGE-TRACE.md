# E2.2 — Coverage instrumentation: which stage removed the turn

Lane 4, branch `claude/hard-ai-e2-lane4`, 2026-09-16.
Slice E2.2 of `../EPIC-PLAN-2026-09-16.md` §4: "trace family → placement
shortlist → action beam → final K → search choice; for each known strong turn,
identify the stage that removed it".

## 1. The stage taxonomy

The generator is a ladder of shortlists. A turn it does not return fell off one
rung. The rungs, in the order `gen/generate.ts run` walks them:

| rung | code | what it can drop |
| --- | --- | --- |
| `upkeep` | `gen/upkeep.ts genKeepSets`, `INTERIOR_KEEP_SETS` | a keep set past index 3 at an interior node |
| `purchase` | `gen/purchase.ts planPurchases` | a buy set outside `cfg.purchase.maxPlans` (12) |
| `promotion` | `gen/promote.ts planPromotions` | a promotion outside `cfg.maxPromotions` (8); ANY second promotion |
| `combo` | `gen/generate.ts buildCombos` | a (plan, promo) pair outside `maxPlacePlans` (16 root, 8 interior) |
| `beam` | `gen/actionsearch.ts dfs`, `cfg.action.widths` | an action line the widths `[6,4,3,2]` never walked |
| `keep` | `gen/actionsearch.ts record`, `tuneKeep` | a line the per-plan `keep` list refused or displaced |
| `final-k` | `gen/generate.ts offer` | an end position displaced against `K` (24 root, 16 interior) |
| `present` | — | nothing under `gen/` removed it |
| `search` | `search/root.ts` | NOT VISIBLE HERE — see §6 |

A verdict names the FIRST rung whose answer is "absent"
(`gen/trace.ts firstRemovingStage`). A two-promotion target is reported as
`promotion` with `multiPromotion: 1`, because one `PlaceCombo` carries one
`promo` index and a second promotion is unrepresentable by construction. Lane 3
owns that audit (E2.1).

## 2. The trace interface

`src/ai/hard/gen/trace.ts` adds a preallocated `GenTrace` record and two
setters: `TurnGenerator.setTrace(trace | null)` (which forwards to both
`ActionSearch` instances) and `ActionSearch.setTrace`.

- A watch is a target end `Kpos` (`watchHi`, `watchLo`) plus an optional packed
  action line.
- With no line the structural rungs report `-1` and only the beam and `K` rungs
  answer, which is all a target known only by its end key can support.
- With a line the trace derives the target's keep-set index, its `BUY` set and
  its `PROMOTE` slots in `resetGenTrace`, once, and every structural rung is
  then a set comparison at a stage boundary.
- Each rung records presence plus its numbers: rank, shortlist size, the
  shortlist's cutoff score, and for the beam the score margin against the list
  that refused it.
- `GenTrace` is NOT a `GenConfig`/`HardConfig` field. `lab/hard-ai/ladder/identity.ts`
  serialises the whole `HardConfig`, and `tests/lab/ablate.test.ts` pins
  `hard@desktop` at `4e7afdf76b32fad…`; a config key would change the champion's
  identity for no behaviour change.
- Cost with `null` installed — every search — is one null test per stage and one
  per turn boundary in `ActionSearch.record`. Nothing is allocated per node in
  either state.

## 3. Byte-identity evidence

`tests/ai/hard/gen-trace.test.ts`, 12 `fuzz-1000.jsonl` positions (the brief
asked for ≥ 8), 14 assertions, all green.

- A no-trace / no-trace control pair runs first, so a failure separates "the
  trace changed the output" from "two identical calls already differ".
- The traced list is compared field by field against the control: candidate
  count, order, `endHi`, `endLo`, `gainCc`, `flags`, `place`, `sig`, `count`
  and every action word, plus the `GenStats` (`placePlans`, `rawLines`,
  `dedupedTo`, `nodes`, `injected`).
- Both a target that IS in the list and a key nothing can produce are watched;
  neither perturbs the output.
- `tests/lab/ablate.test.ts` is unmodified and passing, so the config hash is
  unchanged.

## 4. The tool

`lab/hard-ai/coverage/run.ts`, script `hard:coverage`. Two passes per target.

1. CAPTURE: `generateReference` (K 2000, widths `[40,16,8,4]`, 200 place plans)
   with the watch armed. `ActionSearch.record` fires on every boundary the beam
   REACHES, kept or not, so the packed line comes back even when the reference
   would not have listed the turn. This is needed because the E1 analysis JSON
   records the adviser's turn as display text, not as packed actions.
2. MEASURE: the production cone. `DESKTOP.gen` at ply 0 (a root node) and
   `DESKTOP.genInterior` at ply 1 (a reply node), which is exactly what
   `search/pvs.ts generateAt` picks. Every output row names its cone.

Inputs: `--analysis <dir|file>` (E1 loss analyses) or `--recall-replies <n>`
(the reply items `lab/hard-ai/recall/run.ts` builds from the corpus tail).
Outputs: `coverage.json` (per-row record plus a summary) and `coverage.md`.

No search runs, so a row costs one reference generation plus one production
generation. 56 rows took 65 s; 50 reply rows took 3.9 s.

## 5. The 14 E1.1 losses

`lab/results/hard-ai-e2/coverage/e1.1-losses/` (analysis v1) and
`e1.1-losses-v2/` (analysis v2). Both passes produced identical histograms.
28 root targets and 28 reply targets: the first-consequential and largest-swing
turn of each of the 14 losses, the root target being the adviser's best turn and
the reply target the adviser's refutation of the played turn.

| stage | root | reply |
| --- | --- | --- |
| present | 28 | 19 |
| combo | 0 | 4 |
| beam | 0 | 4 |
| keep | 0 | 1 |
| final-k | 0 | 0 |
| purchase | 0 | 0 |
| promotion | 0 | 0 |
| upkeep | 0 | 0 |

- 28 of 28 root targets were in the generator's own returned list. No rung of
  the generator removed the adviser's best turn at any analysed root.
- Median rank of a present root target: 9, against `K = 24` and returned lists
  of 15 to 36 candidates (forced injections ride on top of `K`).
- Exactly one present root target sat at a rank ≥ `K`, i.e. was there only
  because it was a forced injection.
- 11 of the 28 present root targets were produced by a forced injection.
- The reply misses are 9 of 28: four at `combo`, four at `beam`, one at `keep`.
- All four reply `combo` misses have `planRank` 2, 7, 9, 9 against
  `planCount = 12` and `comboCount = comboLimit = 8`: the buy set survived
  `planPurchases` and `buildCombos` then cut it. Three of the four also carry
  one promotion, so the combined `plan.scoreCc + promo.scoreCc` is what lost.
- The single `keep` miss reached the boundary with `gainCc 12350` and was
  displaced inside a `keep = 16` list, not refused on entry
  (`beamKeepDrops = 0`).
- Three reply targets could not be captured at all: the reference generator
  never reached that end position either. Those rows fall to `beam` with
  `captureLen = 0` and are counted there.
- Median margin of a present root row to the last returned candidate: 545 cc.

This is the coverage answer E1 could not give. At the root, the generator is not
what lost the 14 games. E1.1's single label `strong-candidate-misjudged` is
confirmed for 28 of 28 named turns: the turn was in the list.

## 6. What the trace cannot see

The SEARCH. The trace ends at the returned candidate list.

- A row whose stage is `present` was offered to the root and removed by nothing
  under `gen/`. Whether the root then examined it, and with what score, is
  `search/root.ts`'s record.
- Lane 1 is exposing `RootResult.candidates` behind an opt-in.
- TODO (lane 1 merge): `coverage.json` already carries a `searched: null` field
  on every row. When `RootResult.candidates` lands, fill it from the root record
  keyed on `targetKey` and add a `searched` column to `coverage.md`; the stage
  taxonomy then gains its last rung and `present` splits into "searched and
  mis-scored" and "in the list, never searched".
- Until that merge, no E2 row should claim a root generator gap on this
  evidence, and none should claim an evaluation gap either.

## 7. The reply-node question

E2-PLAN.md reads E1.3 as: at reply nodes the binding width is the action beam,
not the candidate count, because `reply-wide` (kInterior 16 → 32) left
`replyTop1` at exactly base's 0.3636 while only `action-width-wide` moved it
(0.36 → 0.44). E2.2 was asked to confirm or refute that per position.

`lab/results/hard-ai-e2/coverage/recall-replies/`, 50 reply items rebuilt the
way `recall/run.ts` builds them: the corpus tail, the production root generator
plays its own best turn, and the target is the reference generator's best end
state at the node that turn reaches, measured with `DESKTOP.genInterior` at
ply 1.

| stage | reply items |
| --- | --- |
| present | 29 |
| beam | 20 |
| combo | 1 |
| keep | 0 |
| final-k | 0 |

**CONFIRMED.** Of the 21 reply targets the interior list missed, 20 were
removed by the action beam — the widths `[6,4,3,2]` never walked a line to that
end position — and exactly ZERO were removed by `K`: no row reports `final-k`,
and no row reports a displacement against `K = 16` (returned lists ran 9 to 24
candidates, so `K` was not even saturated on most of them). The one remaining
miss is the `combo` shortlist (`planRank 9` of 12 plans against
`comboLimit = 8`). The same shape holds on the 14 E1.1 losses' reply nodes:
four `beam`, four `combo`, one `keep`, zero `final-k`.

Caveats on this row.

- The target here is the reference generator's best by WITHIN-TURN score.
  `recall/run.ts` picks its truth by a depth-2 rescoring, so the item sets are
  not identical and the 29/50 present rate is not `replyTop1` (0.3636).
- The direction is what matters and it is unambiguous: the stage that removes
  the reference-best reply is the action beam, `K` removes none.
- 13 of the 20 `beam` misses are at nodes whose place phase auto-advanced
  (`comboCount = 0`), so no place-phase widening could have reached them either.
- Two of the 20 are upkeep nodes whose target keep set WAS offered
  (`keepPresent = 1`), so the interior keep-set cap is not implicated.
- 13 of the 29 present rows are present because a FORCED INJECTION produced
  them (`beamReached = 0`, `injected = 1`), not because the beam found them.
  The injections are carrying a large part of the reply node's recall.

## 8. Candidate changes the histogram points at

Both are stated as falsifiable equal-time arms. Neither is implemented here.

SUPERSEDED — both are now registered and mechanism-checked in
`E2.3-INTERIOR-ARMS.md`, which FALSIFIES arm 1's prediction below before any
contest (it loses 6 previously-present reply targets on the loss corpus) and
confirms arm 2's mechanism on the loss corpus while measuring zero effect on the
recall corpus. Read that file's §5 for the recommendation; the predictions
below are kept as written so the falsification is legible.

**Arm `interior-action-wide`.** Widen the action beam at INTERIOR nodes only:
`genInterior.action.widths` `[6,4,3,2]` → `[10,6,4,2]`, `gen.action.widths`
unchanged. Prediction: `replyTop1` rises from 0.3636 towards
`ceilingReplyTop1` (0.78), root `top1` is unchanged by construction, and the
contest score against `hard@desktop` at wall:3000 is > 0.5 with a 95% interval
excluding 0. Falsified if `replyTop1` does not move — which would mean the beam
attribution above is wrong — or if it moves and the equal-time contest does not,
which is E1's repeated result for one-factor widenings and would retire the
reply-node hypothesis rather than the instrument. This arm is the cheap half of
E1.3's `action-width-wide` (0.36 → 0.44 on `replyTop1`, which widened root AND
interior and cost +95 then −5 at equal time); the trace says the interior half
is where the recall lives, so the root half's cost can be dropped.

**Arm `interior-place-wide`.** Raise `genInterior`'s `maxPlacePlans` 8 → 12,
leaving `purchase.maxPlans` at 12 and the root at 16. Prediction: the `combo`
misses go to zero (5 rows across both corpora had `planRank` inside
`planCount = 12` but outside `comboCount = 8`), `replyTop1` rises by a smaller
amount than arm 1, and the equal-time contest is the test. Falsified if the
`combo` rows do not clear — the trace can re-run in seconds and say so before a
contest is spent.

**Not justified by this evidence.** Any root-side breadth change. 28 of 28 root
targets were already in the list, so a wider root `K`, a wider root action beam
and more root place plans cannot recover any of the 14 analysed losses. E2.3
should spend its root-breadth budget only after lane 1's `searched` column
exists; on today's evidence the root's problem is downstream of generation.
