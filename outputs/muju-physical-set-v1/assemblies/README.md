# Assemblies

`assemblies.json` is generated by `cad/assemblies.py` from `cad/params.json` and `manifest.json`.
One parameterised rule builds every state; nothing is duplicated by hand. All transforms are
4 × 4 row-major matrices in millimetres. In the board frame, +X runs from file A to J, +Y runs
from rank 1 to 10 (away from Ivory) and +Z is up. The tile top is at Z = 4.0.

| Key | Contents |
|---|---|
| `variants.<v>.piece_states` | 36 per variant (6 elements × ivory/charcoal × T1–T3), 108 in total. Each lists its parts (T3 addition, T2 addition, ownership base, glyph), with GLB/STL paths, matrices, labels and exploded offsets. |
| `variants.<v>.loose` | Each glyph lying flat as a pending summon (the same part as the standing glyph) |
| `loose_beside_piece` | Where the largest glyphs lie beside a T1/T2/T3 piece with four 4-high stacks: rotation and position, overhang area, no contact |
| `variants.<v>.resource_states` | Interior tile with 0 / 4 / 8 / 16 crystals |
| `variants.<v>.tile_join` | A1, B1, A2, B2 corner tiles |
| `variants.<v>.crowded_patch` | 3 × 3 tiles, 144 crystals, four T3 pieces (one rotated 22.5°) and a loose glyph |
| `variants.<v>.board` | 100 tiles with type, colour and coordinate; 504 crystal matrices read from `resourceMap.ts`; the six canonical start pieces |

`cad/validate.py` checks that every referenced file exists and tests every state and scene with
mesh booleans. See `../validation/digital-checks.md`.
