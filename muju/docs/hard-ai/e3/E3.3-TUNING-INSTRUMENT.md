### `npm run hard:corpus`

```
npm run hard:corpus -- --runs <dir> [--runs <dir> ...] [--max-turns n]
  [--holdout-by opening|none] [--holdout-seed <int>] [--holdout-fraction f]
  [--refuse-pool <file>] [--out <dir>]
```

- Source: **existing ladder replays**, not self-play. Each `--runs <dir>` is a
  ladder result directory with `games.jsonl`, `manifest.json` and `replays/`.
- Every game with a recorded replay is rebuilt through the canonical engine by
  `lab/hard-ai/analyze/replay.ts reconstruct`, which refuses a replay that no
  longer reproduces its own snapshots. 520 of 520 games rebuilt without a
  mismatch in the smoke run.
- A turn boundary on the game path is a **macro node** when the side to move
  still has all four actions (`p.actions === ACTIONS_PER_TURN`). A boundary
  with fewer — the first turn after an opening that spent part of it — is
  counted (`nonMacroBoundaries`) and dropped, because DESIGN §5.12.1 defines
  feature 19 `ActionsLeft` as "0 at macro nodes".
- **Quiet**, DESIGN §5.15 verbatim: no `killNow` entry with `minActions <=
  p.actions` for either side, and `home[side].actionsToCorner > 4` for both
  sides. Fields: `tables/kill.ts KillTable.entry[slot].minActions`
  (`KILL_IMPOSSIBLE = 255` when no plan exists) and `tables/home.ts
  HomeSafety.actionsToCorner` (`HOME_NEVER = 127`). Both are read off the
  level-2 `NodeTables` the evaluator itself built (`Evaluator.lastTables`), so
  the quiet test and the feature vector describe one table build.
- Features come from `Evaluator.full(p, side, scratch, 0, outFeatures)` — the
  full three-stage evaluation, `NULL_METER` not needed because `full` spends no
  work.
- Row format `muju-texel-v1`, DESIGN §5.15's eight fields plus seven additive
  ones:

```json
{"schema":"muju-texel-v1","id":"g3-s25_0_0-A-white-p0","result":1,"side":0,"turn":2,
 "features":[58 ints],"material":[18 counts],"kpos":"04e3b9b19f0e635b",
 "opening":"g3-s25","pool":"lab/hard-ai/ladder/openings/e1-baseline.jsonl",
 "handicap":0,"game":"g3-s25_0_0-A-white","run":"lab/results/hard-ai-e1/baseline",
 "actions":4,"split":"train"}
```

- `result` is from the **row side's** point of view: 1 that side won, 0.5 draw,
  0 lost.
- `material` is 18 **signed counts** `n_row[d] − n_other[d]`, not cc. See "The
  material block is not a feature" below.
- `manifest.json` (`muju-texel-corpus-manifest-v1`) carries the engine config
  hash, the weights hash, label and version, the run list with each run's
  opening pool and its sha256, counts (games, turn boundaries, macro nodes,
  positions), draw share, quiet share, per-result counts, the terminal
  histogram, per-opening counts, per-pool counts, the refusal tallies and the
  split.

### `npm run hard:texel`

```
npm run hard:texel -- --corpus <dir> --iterations n [--out <dir>]
  [--steps 100,10,1] [--refit-k] [--label <name>]
```

- Model: `p = sigma(k · evalCc)` with `sigma(x) = 1/(1+e^-x)`, DESIGN §5.15's
  `sigma(k·eval)` taken literally, so `k` carries the 1/cc scale (fitted values
  land near 4e-4 … 2e-3).
- Loss: mean log-loss `-(r ln p + (1-r) ln(1-p))`, the quantity DESIGN §5.15's
  gate ("held-out log-loss strictly improves") and M18's
  `texel.heldOutLossAfter < texel.heldOutLossBefore` name. A draw contributes
  the symmetric `r = 0.5` term.
- `k` is fitted first on the training split by ternary search on `log10 k` over
  `[-7, 0]` plus refinement, then held fixed (DESIGN: "fit `k` first").
  `--refit-k` re-fits it after each iteration.
- Coordinate descent, integer steps, **schedule 100 → 10 → 1 cc**. One
  iteration sweeps each step size over every free parameter, trying `+step`
  then `-step` and continuing in the direction that lowered training loss until
  it stops lowering it, capped at `MAX_RUN_PER_PARAM = 50` consecutive accepted
  steps per parameter per sweep. An iteration that accepts nothing ends the
  fit.
- Pinned: `material[fire_1] = 300` (DESIGN §5.12), and `w[F.Material]`, which
  multiplies nothing (below). 74 of the 76 parameters are free.
- Output `weights.json` (`muju-weights-v1`: `version, label, w[58],
  material[18], k, lossBefore, lossAfter, corpus`) plus
  `heldOutLossBefore/After`, `trainLossBefore/After`, `allIntegers`,
  `fire1Pinned`, the per-iteration trace and `"candidate": false`. `lossBefore`
  and `lossAfter` are the HELD-OUT numbers, so M18's gate expression reads
  either spelling. `report.md` beside it.

### The material block is not a feature

`Evaluator.stage0` scores material as `Σ_d material[d] · (n_root[d] −
n_other[d])` from the 18 tunable `Weights.material` params
(`src/ai/hard/eval/evaluate.ts:122-127`), while `extract` writes a separate
WEIGHT-FREE catalogue-prior value into `out[F.Material]`
(`src/ai/hard/eval/features.ts:174`). `Evaluator.full` copies `this.f` into
`outFeatures` untouched (`src/ai/hard/eval/evaluate.ts:163-167`). So the engine's
score is

```
score = Σ_{i≥1} w[i]·f[i] + Σ_d material[d]·(n_row[d] − n_other[d])
```

and `w[F.Material]` multiplies nothing. Measured: exact on **730 of 730** macro
nodes from 20 `hard-ai-e1/baseline` replays, of which **665** had a non-zero
`f[F.Material]` and would have disagreed if index 0 contributed. That is why a
row's `material` field holds counts and why the fit pins `w[0]`.

The header of `src/ai/hard/eval/features.ts:29-31` says the opposite — that
`full()` "overwrites `out[F.Material]` with the weighted value … so `score ===
Σ w·f` stays exact under tuning". No such assignment exists in
`evaluate.ts`, and `evaluate.ts`'s own header (lines 22-25) states the
behaviour the code has. Filed as a proposed amendment (`amendments/lane8.md`);
lane 8 may not edit `src/ai/hard/**`.

## Leakage rules

Which openings a corpus may ever be built from:

- **May be trained on** — the development stratum, `e0-openings.jsonl` (16) and
  `e1-dev.jsonl` (48), and through it `e1-baseline.jsonl`, which is a copy of
  rows from both (`ALLOCATION.md`).
- **Refused, always** — `e1-sealed.jsonl` (E6.2 acceptance; any earlier run
  voids it) and the whole of `e2-val.jsonl` (rows 32-63 are E3's confirmation
  openings, rows 0-31 stay reserved for E2).
- **Contested** — `e1-val.jsonl` and `e1-val2.jsonl`. `E3-PLAN.md`'s lane
  brief allows "the E1 validation blocks already spent"; `ALLOCATION.md`'s
  frozen stratum rule says validation is "never tuned against". The tool does
  not resolve this: it admits those rows, records `pool` on every row and
  `perPool` in the manifest so the mix is visible, and offers `--refuse-pool`
  so a corpus can exclude them without a code change. Ruling requested in
  `amendments/lane8.md`.

Refusal is enforced three ways and each is counted separately in the manifest:

1. **by pool** — a run whose `manifest.openings.path` is a refused file is
   refused whole, before a single replay is opened.
2. **by id** — the opening id sets read out of the refused pool files.
3. **by prefix** — `e2-` only.

`e1-` is **not** a prefix rule: `e1-sealed.jsonl`'s ids are `e1-g3-s270`-shaped
and so are `e1-dev.jsonl`'s and `e1-val.jsonl`'s, because all three came from
one `--id-prefix e1-` generation (`ALLOCATION.md`, "Commands that produced
them"). A prefix rule on `e1-` would refuse the one stratum tuning may use.
`tests/lab/texel.test.ts` asserts both directions: every id of both refused
pools is refused, and no id of `e0-openings.jsonl`, `e1-dev.jsonl`,
`e1-val.jsonl`, `e1-val2.jsonl` or `e1-baseline.jsonl` is.

Verified end to end: a corpus run over the `calib` and `reply-wide` ladders
with `--refuse-pool e1-val.jsonl --refuse-pool e1-val2.jsonl` produced 0 rows
and `refusals pool=128`.

## What the corpus cannot price

In the 1,111 training rows, **20 of the 58 features are identically zero in
every row**: `HomeInvaded`, `Infiltration`, `HomeThreat`, `Hanging`,
`HangingBuy`, `StrandPunish`, `KillAvailable`, `CleaveExposure`,
`AnchorFragility`, `BlockingDeficit`, `CornerInfiltration`, and invariants 6,
7, 8, 10, 11, 12, 15, 18, 19. Six of the 18 material params never appear
either: `fire_2`, `lightning_3`, `shadow_2`, `shadow_3`, `metal_2`, `metal_3`.

This is structural, not a sampling accident. The quiet rule selects positions
where no side can kill inside its action budget and neither corner is reachable
in four actions, which is exactly the condition under which the kill and home
blocks are zero. **A quiet corpus cannot price the tactical half of DESIGN
§5.12.1's feature table.** Whatever E3.2 concludes about `Hanging`,
`KillAvailable` or `HomeThreat` has to be measured some other way.

## What is missing

1. **Self-play corpus generation.** DESIGN §5.15 and M18 specify `hard:corpus`
   as self-play at fixed work (default 25,000) with opening diversity from the
   797 census positions, both handicaps, sharded, with a `DrawPressure`
   perturbation path when the draw share exceeds 70 %. None of that is here.
   This tool reads recorded games only; `--games`, `--work`, `--handicaps`,
   `--shards` and `--seed` are not accepted flags.
2. **The 10,000-position bar.** M18's gate is `corpus.positions >= 10000 &&
   corpus.drawShare < 0.70`. Draw share is fine (0.0115). Positions are not:
   520 games of existing replays yielded 1,335. At the measured 2.57 quiet rows
   per game, the bar needs roughly 3,900 games; all the hard-AI result
   directories together hold 678 games with recorded replays. A self-play
   generator is the only way to the gate.
3. **SPSA.** `lab/hard-ai/tune/spsa.ts` was not written and is not in this
   slice. `npm run hard:spsa` remains broken.
4. **The book.** `lab/hard-ai/book/build.ts` (`hard:book`) is M18's other half
   and is untouched here.
5. **A regularised or rarity-guarded fit.** DESIGN §5.15 specifies none, and
   the smoke run shows what that costs on a small corpus.
6. **Any measurement of a tuned vector.** No ladder row, no exam, no tactics
   suite has seen one. Under M20 that is the whole remaining distance.
