# E1.5 — `calibrateCold`: the E1.4 §5 patch as a switchable arm

Written 2026-09-16 on `claude/hard-ai-e1-lane8`. This lane BUILDS and PRICES
nothing: it lands the patch E1.4 §5 chose as an arm that can be turned on, the
lab plumbing its own acceptance contest needs, and one measured check. The
champion `hard@desktop` is untouched, byte for byte.

## 1. What the flag does

`TimeConfig` gains `calibrateCold`. When it is on, `HardEngine.searchTurn`'s
MEASURED branch (no `work` given) does one extra thing, once per engine: it
measures this box with a REAL search before it sizes the turn's rung.

```
enteredAt = now()
pack, level-2 tables, book probe, tms = targetMs(...)
if (time.calibrateCold && profile.samples === 0 && !coldProbed) {
  coldProbed = true
  deadlineMs = enteredAt + <window>            // armed BEFORE the probe
  probe  = searchRoot(this, state, { work: COLD_PROBE_WORK })   // WORK_LADDER[0] = 25,000 units
  probeMs = <its wall time>                    // -> stats.calibratedMs
  if (probeMs >= 20 && probe.work >= 12,500)   // A16's floors, unchanged
    profile = updateProfile(profile, probe.work, probeMs)       // samples 0 -> REPLACES
                                               // -> stats.calibratedUnitsPerMs
  rungMs = tms - (now() - enteredAt)           // size for what is LEFT
}
work = chooseWork(profile, rungMs)
... the measured search as today ...
```

- ONE RUNG OF REAL SEARCH. `COLD_PROBE_WORK` is `WORK_LADDER[0]` — the smallest
  rung the ladder has, and the one `chooseWork` clamps every budget up to. It is
  also, by construction, at or above A16's `MIN_PROFILE_SAMPLE_WORK` floor of
  half a rung, so a probe that actually spends its budget is always a usable
  sample; anything smaller could not be.
- `updateProfile` from `samples: 0` REPLACES rather than blends, so the measured
  rate is the profile, and the turn's own search then blends into it at α = 1/4
  exactly as before.
- ONCE PER ENGINE, whether or not the sample survives the guard (`coldProbed`).
  A position the search finishes inside 25,000 units measured the position, not
  the box, and did not need a rung; `updateProfile` picks the profile up from
  the first real search that clears the floors, as it does for the champion.
- THE DEADLINE COVERS IT. The watchdog is armed at `enteredAt`, before the
  probe, so probe and search together fit the allowance and the probe can itself
  be cut on a box where 25,000 units is already the whole turn. With the flag
  off, `calibratedMs` is 0 and the anchor is exactly where A11 put it.
- THE RUNG IS SIZED FOR WHAT IS LEFT: `tms - (now() - enteredAt)`, not `tms`.
  That charges the packing and the level-2 build too, which is right, because
  the deadline window starts at `enteredAt` as well.
- THE PROBE'S PLAN IS THE TURN'S FALLBACK. It bought a completed rung of real
  search, so when the main search comes back with nothing usable — no actions,
  or the `phaseEndAction` `iterativeDeepening` falls back to when the deadline
  cut it before depth 1 — the probe's plan is substituted. A pack error or a
  replica divergence (`result.fallback` set) is not substituted: those say the
  plan cannot be trusted, not that none was found.
- THE PROBE LEAVES THE TABLES WARM. The transposition table, proof cache and
  ordering tables are cleared once per `searchTurn`, not once per `searchRoot`,
  so the 25,000 units are spent on the position rather than thrown away. The
  price: a probing turn's main search is not the same object as a cold search at
  the same rung. It is a wall-mode behaviour of one ablation arm, and fixed-work
  mode — every determinism gate — never probes.
- `stats.calibratedMs` is the probe's wall cost and `stats.calibratedUnitsPerMs`
  the rate adopted (0 when no probe ran, and 0 when the probe ran but the guard
  rejected it, so an artifact can tell the two apart).
- Fixed-work mode never reaches any of this: the whole block is inside the
  `else` branch, and that mode reads no clock at all.
- `npm run hard:deps` passes: the probe's two clock reads are `search/time.ts#now`
  inside `engine.ts`, which is already allowed.
- `calibrate()` is UNTOUCHED, for its existing caller
  (`tests/ai/hard/interfaces.test.ts`). Nothing in the search path calls it;
  §4 is why.

Nothing else moves — `WORK_LADDER`, `targetMs`, `updateProfile`, A11's deadline
semantics and A16's guard are all as they were.

## 2. The identity guarantee

`hard@desktop` at `wall:3000` still resolves to

```
4e7afdf76b32fadfab2d11577cb610c8f9f1a491b5153e70b87b0774403600cd
```

pinned in `tests/lab/ablate.test.ts` (`DESKTOP_WALL3000_HASH`) and re-checked
after this change. `hard@lab` and `hard@ablate:base` share it, as before.

HOW, and the one deviation from the brief. `ladder/identity.ts` serialises the
WHOLE resolved `HardConfig`, `time` included, so writing `calibrateCold: false`
into `makeConfig` would have put the key into every resolved configuration and
moved the frozen champion's hash for no behaviour change — orphaning every E1
row measured under it (A12). The field is therefore declared OPTIONAL and left
UNSET on every shape (`canonicalJson` drops a key that is not present); the
engine reads it as `=== true`, so absent means false everywhere. The only
configuration that carries the key is the arm's.

`hard@ablate:calib` at `wall:3000` is

```
3f356cb629521b046205eae5752e282a3a30871eaa6b41e524e34a2c134a8d70
```

The arm's hash is UNCHANGED by E1.5's revision of the mechanism, and that is
correct: `resolvedConfigHash` hashes the CONFIGURATION, and the configuration
(`calibrateCold: true`) is the same whether the flag drives `calibrate()` or a
probe search. What changed is the code, which the manifest records separately —
`baselineIdentity().sources.ai` is now
`632be18753e44afe1c38f54ec399667d86ca1207f34d98a56e3d33f641546f70`. Any row run
against the first mechanism would have to be separated by that hash, not by the
config hash; no row was run against it.

The arm is registered in `lab/hard-ai/ablate/arms.ts` with a new factor,
`'time'` (the whole `TimeConfig` block), and its patch is
`{ time: { ...DESKTOP.time, calibrateCold: true } }` — a whole `time` object,
because `hardConfigFor` composes an arm patch with a flat spread and a nested
partial would drop `minMs`/`maxMs`/`baseMs`/`abortFactor`. The registry's
one-factor invariant (`factorsOf` diff, and `maskFactor` restoring the block and
re-hashing to base) covers it like every other arm. `rootDiagnostic` is false:
the recall instrument funds items with fixed work and reads only
`gen`/`genInterior`, so it cannot see a time-allocation arm at a root node or
anywhere else — this arm is priced by a ladder row, never by a recall column.

## 3. Per-seat A16 attribution (lab only, no engine change)

E1.4 §5 listed this as a prerequisite: the A16 columns were `n/a` in the `k96`
row because `bots/hard.ts`'s counters are PROCESS-WIDE and `ladder/run.ts`
attributes them only when exactly one arm is `hard@`. H_T's prediction (a) is
about `firstSearchAborted`, so it was unmeasurable in its own Hard-vs-Hard
contest.

What changed:

- `createHardBot` keeps a per-INSTANCE copy of every counter, reset in
  `onGameStart`, incremented alongside the process-wide ones. `maxTurnMs` is a
  true per-game maximum per instance, which the process-wide high-water mark
  cannot be.
- `EngineBot` gains an optional `timing()`; `lab/harness/runner.ts` calls it for
  each seat and writes the result into `PlayerGameStats.hardTiming`
  (`HardSeatTiming` in `lab/harness/types.ts`, structurally identical to
  `HardBotTiming`, spelled there so the harness keeps no dependency on
  `lab/hard-ai`).
- `ladder/run.ts` sums per-seat counters per ARM and PREFERS them; the old
  sole-`hard@`-arm path over `GameRecord.hardTiming` survives as the fallback for
  records written before the field, and an arm with neither source still reports
  `null` rather than 0 (a missing count is not a zero rate).
- `hardBotTiming()` is unchanged and explicitly documented as the process-wide
  SUM; `worker.ts#hardTimingDelta` and `GameRecord.hardTiming` are untouched.

Tests: `tests/lab/turn-allowance.test.ts` (two hard bots in one process report
distinct `firstSearchAborted`, and a bot re-arms its own counters per game, while
the process-wide sum still adds up) and `tests/lab/ladder-runner.test.ts`
(`computeMetrics` attributes `searches`/`abortedSearches`/`abortRate`/
`firstSearchAborted`/`budgetExhausted` per arm in a `hard@ablate:calib` vs
`hard@desktop` build; an arm with no per-seat data is still `null`; per-seat wins
over the process-wide fallback).

## 4. The measured check, and why `calibrate()` was rejected

Three mid-game authored positions (`lab/hard-ai/positions/authored.jsonl`:
`promotion-kill` t4, `occupied-corner` t1 action, `endgame-dry` t41), the FIRST
search of a FRESH engine, `targetMs: 3000, deadlineMs: 3000`, 2026-09-16 on this
box under the usual two-slot heavy load.

(The last row is the one case in six where the probe did not lower the rung:

Read honestly:

1. The probe measures what `chooseWork` is asking about. Its rate (56-145
   units/ms) lands on the same scale as the rate the engine's own search then
   reports (62-134 units/ms), which is the whole difference from §4.2.
2. Five of six first searches now end on the WORK rung, at 1005-1634 ms against
   a 3,000 ms allowance, where the champion's end on the deadline at 3000-3020 ms
   in four of six. The rung is 100,000-200,000, as E1.4 §5 predicted the patch
   should produce.
3. The probe costs 101-443 ms, more than `calibrate()`'s fixed 40 ms, and it is
   spent out of the allowance rather than added to it (total wall 1106-1821 ms
   for the calib rows against the champion's 2595-3025 ms). The 443 ms outlier
   is the first real search in that process: the probe absorbs the JIT warm-up
   that the champion's first search otherwise pays inside its own deadline.
4. `endgame-dry` warm shows the mechanism's honest limit: quantisation. A
   measured 145 units/ms still buys the 400,000 rung at 3 s, so a position whose
   search needs more than the allowance is still deadline-cut. The patch fixes
   the COLD MISCALIBRATION, not the factor-2 ladder (E1.4 §5 said as much).

### 4.2 Rejected: seeding from `calibrate()` (the literal E1.4 §5 patch)

E1.4 §5 proposed `profile = this.calibrate()` — DESIGN §4.17's fixed 40 ms
micro-benchmark. That was implemented first and measured on the same three
positions. It is kept here as the evidence for rejecting it:

| position | arm | rung | calibMs | elapsedMs | stopReason | profile after |
| --- | --- | ---: | ---: | ---: | --- | --- |
| promotion-kill | `hard@desktop` | 400,000 | 0 | 2325 | work | 83/1 |
| promotion-kill | calib via `calibrate()` | **800,000** | 40 | 2962 | **abort** | 324/2 |
| occupied-corner | `hard@desktop` | 400,000 | 0 | 3020 | abort | 127/1 |
| occupied-corner | calib via `calibrate()` | **800,000** | 40 | 2965 | abort | 348/2 |
| endgame-dry | `hard@desktop` | 400,000 | 0 | 3005 | abort | 105/1 |
| endgame-dry | calib via `calibrate()` | **800,000** | 40 | 2962 | abort | 264/2 |

(JIT-cold runs were the same shape: 298-306 units/ms, rung 800,000 every time.)

`calibrate()` returns **264-348 units/ms** where the same engine's own search
then measures **75-127** — three to four times too fast. `chooseWork(300, 3000)`
= 900,000 of budget, which quantises to **800,000, one rung ABOVE the cold
default's 400,000**. The patch as literally specified therefore made the cold
rung WORSE: on `promotion-kill` the champion's first search FINISHED on the work
rung (2325 ms) and the `calibrate()`-seeded arm's was deadline-cut.

Why: `calibrate()` is a hot loop over ONE position (`createInitialGameState`),
re-running `buildTables` + `Evaluator.full` with perfect cache and branch
behaviour, and it charges itself only KILLTABLE + EVAL1 + EVAL2. A real search
spends most of its units in turn generation, action search and canonical replay
over thousands of distinct positions. The micro-benchmark measures a different
machine from the one `chooseWork` is sizing for.

H_T's prediction (a) would have failed its own contest under that mechanism, and
E1.4 §5's rule would have reverted the patch without ever testing the hypothesis
— "the cold profile costs strength" — that it exists to test. Replacing the
instrument rather than the hypothesis is why §4.1 is what goes to the row.
`calibrate()` itself is unchanged and still serves its existing caller.

Reproduce either table: `lab/hard-ai/positions/authored.jsonl` + a fresh
`HardEngine` per row with `hardEnginePatch('desktop')` /
`hardEnginePatch('ablate:calib')`, `searchTurn(state, { targetMs: 3000,
deadlineMs: 3000 })`, reading `engine.ctx.meter.limit`,
`result.stats.calibratedMs`, `result.stats.calibratedUnitsPerMs`,
`result.stats.elapsedMs`, `result.stats.stopReason`.

`--openings-skip 16` is the 16 `e1-val` openings no pricing row has used (A15,

an analyser.

DECISION RULE (E1.4 §5, unchanged):

- RETAIN only if `firstSearchAborted` < 10% of games for the calib arm AND
  score > 0.5, with the pair-aware interval reported per stratum and
  `overrunRate` / `budgetExhausted` / `maxTurnMs` no worse than the champion's.
- Otherwise REJECT and revert the flag (E4.3: revert a failed improvement, do
  not stack). Rejecting means deleting the arm and the flag, not leaving it off:
  a dead flag in `TimeConfig` is a configuration field a later reader has to
  re-litigate.
- P6 still applies: report `maxTurnMs` per game, and hold the row's timing
  columns as not citable if the 20-180 s turns of the `k96` row recur
  (`docs/hard-ai/e1/P6-TURN-TIME-EXPLOSION.md`).

Both arms are `hard@`, so the A16 columns of this row come from §3's per-seat
counters. That is the only reason the row can be read at all.

WHAT §4.1 PREDICTS, recorded before the row runs. H_T(a) —
`firstSearchAborted` under 10% of games — is now plausible: five of six measured
first searches ended on the work rung. It is NOT assured, because the row plays
from `e1-val` openings rather than these three positions, and a position whose
measured rung is still 400,000 (the `endgame-dry` warm row) is deadline-cut like
the champion's. H_T(b) — the arm does not lose at equal time — is the open
question and the reason the row is worth the two heavy slots: the patch trades
101-443 ms of probe for a rung the box finishes, and whether that is worth Elo is
exactly what 32 pairs are for. This lane asserts neither.

change the turns 2–7 decisions the losses were classified at.

turn is NOT where the strength is. The `maxTurnMs` of 11.9–15.7 s in both arms

remains"), down from 170 s.
